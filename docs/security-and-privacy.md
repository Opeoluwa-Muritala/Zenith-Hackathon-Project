# Security and privacy

BVNs are validated, HMAC-hashed, and represented by last four digits; raw BVNs and OTPs are not persisted to the database. The explicitly enabled development inbox retains OTPs in process memory temporarily. OTP challenges use a salted HMAC, and refresh tokens are stored as hashes. Discovered account numbers, provider-link account IDs and registered device tokens use versioned Fernet ciphertext. Previous field keys can be supplied by key ID for decryption during rotation. Mono request bodies are not logged by the provider adapter. Consent ownership is checked on protected ledger reads.

When `FIELD_ENCRYPTION_KEY` is absent, field encryption derives a separate Fernet key from `MONO_SECRET_KEY` using HKDF and labels ciphertext `mono_derived_v1`. The original Mono secret must remain available for decryption after rotation, or the derived key must be supplied under that ID in `FIELD_ENCRYPTION_PREVIOUS_KEYS`. A dedicated field key avoids this operational coupling.

The backend is read-only with respect to financial data: the provider adapter implements account linking, reads, categorisation, and unlinking, not payment initiation. Complete user wipe, retention enforcement, audit events, distributed rate limiting, verified production OTP delivery, and full NDPA operational processes are not implemented. Without either configured secret, the development encryption fallback is process-random and must not be used for persistent real data. The legacy mock BVN route is disabled in production and Mono mode.

The hosted demo inbox requires explicit demo mode, a configured presenter password and allowlisted fictional identities. It is excluded from OpenAPI, returns no-store responses, and cannot run in production. Codes are kept only in one worker's memory; the database stores challenges as hashes. Validation errors omit submitted sensitive values. Webhook processing stores event identifiers, state and timestamps without retaining the financial payload. No live security or compliance certification is claimed.
